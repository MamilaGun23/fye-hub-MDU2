03 / THE THINKING

Designed around
real responsibilities.

The engineering decisions follow the way a student support programme works: people need different tools, and some actions need oversight.

01

Role-aware journeys

Dedicated workspaces keep student, mentor, supervisor, and admin tasks focused. Database policies and functions remain the authority for data access.

02

Review before publication

Mentor applications and event requests move through explicit review steps, keeping approval decisions visible in the workflow.

03

A deliberately small stack

HTML, CSS, and JavaScript deliver the interface. Express serves the app; Supabase supplies authentication, storage, and PostgreSQL workflows.

04 / WHAT COMES NEXT

Built to learn.
Documented to grow.

The next steps are a reproducible base database schema, live role-permission verification, and further accessibility review. Adoption and student outcomes have not been measured.
